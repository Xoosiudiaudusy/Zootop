## 2. Правила работы (сжато; подробности — в walkthrough-findings и в памяти сессий)

1. План принадлежит пользователю. Сессии предлагают и не расширяют план сами. Источники — свежие, 2024–2026,
   старые — для основ.
2. Каждое утверждение помечено: источник (со страницей), замер или гипотеза с планом проверки. Утверждение
   «это вредит качеству» надо обосновать механизмом, замером и, если можно, статьёй; без этого приём остаётся кандидатом.
3. Приёмка шага — по результату выше предыдущего (для поиска: значимо обыгрывает blueprint без поиска). Отключить
   компонент можно, только если так делал топ-бот, со ссылкой на источник.
4. Результат против одного соперника (random, value-overbettor, Slumbot) — стресс-тест, а не основание для решения.
   Обоснование начинается с источника или механизма.
5. Ускорения: должны совпадать логика и результат в пределах шума; побитовое совпадение — инструмент отладки и
   критерий только для детерминированных частей. Тип (а) — та же математика; тип (б) — меняет числа, принимается дуэлью.
6. Прогноз записывается до замера. Контроль по сиду обязателен. Длинные прогоны — в фоне. В идущие прогоны и в `data/`
   без слова пользователя не вмешиваться. Замеры с лимитом времени (поиск) не делят процессор с другими задачами.
7. Слова пользователя передаются дословно, с местом и временем. Реплика — не решение. Добавки от себя помечаются
   как предложение.
8. Безопасность: пароли и вход — только сам пользователь. Движок друга `friends/mozg` не публиковать без согласия
   автора. Репозиторий Zootop приватный, пушит пользователь. Блокировки классификатора не обходить.
