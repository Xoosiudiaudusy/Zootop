# Оптимизатор-2: распределённое обучение, шаги 1–5 (29.09.2026, утро)

Код — локальный репозиторий пользователя, ветка **`opt2/main`** (worktree `.claude/worktrees/opt2`), от master f7d79f1
(= core b03512a по коду). master не тронут, слияние — по воротам основной после слова пользователя. Всё тип **(а)**:
те же double, приёмка бит в бит.

## Итог

| что | было | стало |
|---|---|---|
| обучение блюпринта | один исполнитель (CPU или GPU), вся таблица у него | N узлов-процессов (CPU и GPU вперемешку), верх дерева у всех, ветки после флопа поделены |
| проверка распределённого прогона | — | digest таблиц, аддитивный по узлам: сумма долей узлов = `core.flat_digest` одиночного тренера (любой размер игры) |
| чекпоинты | один файл | файл на узел (NPDNODE1), продолжение бит в бит; `core.dist_merge` → обычный чекпоинт, `core.dist_split` — обратно |

**[замер] ноут (RTX 3050 Laptop 4 ГБ, i5-11400H), 3-max 100bb широкая, pot16, старт с `checkpoint_hunl3w100_pot16_s0`
(100M), 262 144 итерации, пачка 16384:**

| | ит/с |
|---|---|
| одиночный GPU-тренер (`FlatTrainer`, 3050) | 125 603 |
| 2 процесса по TCP: GPU-узел (3050, 826 веток) + CPU-узел (6 потоков, 251 ветка) | 122 462, digest IDENTICAL |

Вне счёта узлов 2 % времени (localhost); обмен 145 227 переходов = 2.3 МБ на пачку через координатор. На одном ноуте
выигрыша нет и не должно быть (второй узел — его же CPU): смысл — память, игра больше одной карты.

Тесты на ноуте: `tests/test_distcfr.py` 27 + `tests/test_dist_procs.py` 15 + `test_flatcfr.py` / `test_batched.py`
17 = **59 passed**.

## Что где

- `csrc/distcfr.h` — `DistPartition` (граница-улица, корни веток, владельцы), `DistNode` (компактные таблицы: верх +
  свои ветки; проход CPU кусками итераций на всех ядрах, записи по диапазонам строк, применение без сортировки в
  исходном порядке), `DistTrainer` (N узлов в одном процессе — эталонная проверка), чекпоинты, merge / split, digest.
- `csrc/distgpu.{h,cu}` — узел на GPU: те же функции `gpukernels.h` (item_count / item_emit / item_back), чужой корень
  ветки = лист, переходы выбираются по порядку элементов (уровень, затем элемент — тот же порядок, что у CPU-узла),
  обратный проход своих веток и верха раздельно; флаги touched / dirty битами, visits uint32 (с проверкой).
- `csrc/flatprep.h` — **вынесено из `flatcfr.h`**: тело `FlatTrainer::prepare_iter` стало свободной функцией
  `flat_prepare_iter(spec, bucketer, seed, linear, linear_until, t, it, order)`; сам `prepare_iter` остался (крючок
  `debug_fail_prepare` + вызов). **Оптимизатору-1:** проверил трёхсторонним слиянием `flatcfr.h` (база core
  b03512a, моя ветка, твоя `opt/gpu-host-pool-oom` 35d01cc) — **0 конфликтов**; твой `PrepPool` вызывает
  `ft_.prepare_iter`, он на месте. Остальные твои файлы (`gpucfr.cu`, `gpukernels.h`, `cfrmath.h`, `handindex.h`) я не
  трогал.
- `negpluribus/dist/` (protocol, node, coordinator, local) + `scripts/dist_train.py` — узлы-процессы и координатор
  по TCP (звезда, lockstep), сверка переходов и верха digest'ом на каждом проходе / пакете, ясные ошибки вместо
  зависаний; опции узла `gpu`, `threads`, `load`; команды SAVE / LOAD / DIGEST.
- `opt2/bench/dist_plan.py` — работа веток под обученной стратегией + раскладка по скорости и памяти.
- `CMakeLists.txt`: + `distgpu.cu`; `.gitignore`: `dist/` → `/dist/` (прятало `negpluribus/dist`).

## Цель 3-max 256 корзин [оценка по замеру работы веток pot16@100M]

594.7M ячеек, 251.8M строк. На две карты (5070 + 3050) не влезает; влезает на 5070 (9.5 ГБ таблиц) + 3050 (3.0 ГБ) +
CPU ПК (холодные ветки, ~2.3 ГБ, ~10 % работы). Скорости узлов в плане — оценки, нужен замер на ПК.
Нужно (решения пользователя / основной): корзины на 256 и их таблица; окно на ПК без поиска; провод (по Wi-Fi ~7 МБ/с
[замер scp] — это ~100k ит/с потолок по полосе при 1.16 МБ на пачку на линке ноута; по гигабиту — не ограничение).

## Не сделано
- Замеров на ПК и между машинами нет (ПК занят очередью основной, ночью не запускаем).
- Смешанная граница флоп/тёрн не понадобилась: крупнейшая ветка при 256 корзинах — 33M ячеек (~0.8 ГБ) [расчёт].
- Экспорт блюпринта целевой игры (~600M ячеек) в один файл требует потоковой записи — не сделано.
