# 3-max wide на 256 корзин на одном ПК: горячие ветки в VRAM 5070, холодные в памяти хоста (вариант 3)

К решению пользователя «где учить 256». Метки: [замер] / [расчёт] / [оценка] / [гипотеза]. Кода нет.

## (а) Память

**Таблицы узла** [расчёт по замеру `bench/game_size.py`, раскладка GPU-узла]: 594.7M ячеек × 24.125 Б + 251.8M строк
× 8 Б + записи решений 0.09 ГБ = **16.45 ГБ**. Верх — 0.04 ГБ.

**VRAM 5070** (12 ГиБ = 12.9 ГБ) [оценка]:

| статья | ГБ |
|---|---|
| дисплей / WDDM | ~0.8 |
| контекст CUDA | ~0.3 |
| буферы пачки: элементы прохода ~16M × 49 Б × 1.25, обновления, нагрузки, сортировка | ~1.2 при проходе 16384, ~0.7 при 8192 |
| **под таблицы** | **~10–10.5** |

**В закреплённую память хоста — 6.0–6.6 ГБ** [расчёт: работа веток замерена на pot16 при 100M, байты пересчитаны на
256]. Это самые холодные ветки по работе на байт (609–660 из 1077), и на них приходится **0.5–0.75 % работы**.
Распределение крутое:

| самые холодные | доля работы |
|---|---|
| 3 ГБ | 0.08 % |
| 5 ГБ | 0.29 % |
| 7 ГБ | 1.02 % |
| 9 ГБ | 5.15 % |

**RAM ПК** (32 ГБ без подкачки) [оценка]:

| статья | ГБ |
|---|---|
| система и приложения (цифра сенсея) | ~10 |
| закреплённые холодные таблицы | 6.6 |
| процесс узла: игра, `info_dec` на время загрузки, корзины | ~1.5–2.5 |
| **итого в работе** | **~18–19** — влезает |

**Пик чекпоинта:** сейчас `save_tables` собирает на хосте полные копии (regret + ssum + visits + touched ≈ 11.8 ГБ).
Вместе с остальным это ~30–31 ГБ — **на грани 32 ГБ, так нельзя**. Нужно сохранять и загружать кусками по
~0.25–0.5 ГБ, тогда пик ~19 ГБ. Файл чекпоинта на диске ~12 ГБ.

## (б) Штраф PCIe 4.0 ×16 (~25 ГБ/с, для мелких случайных обращений ~10–12 ГБ/с полезных) [оценка]

- **Трафик таблиц за пачку 16384** — ~8M случайных обращений по ~48 Б ≈ 0.4 ГБ:
  - σ строк в прямом и обратном проходе;
  - чтение и запись строк при сложении;
  - пересчёт σ изменённых строк.
- **Холодные ветки берут свою долю w от этого трафика:**

  | w | через PCIe за пачку | время | замедление пачки ~14–20 мс |
  |---|---|---|---|
  | ≤ 1 % (обученная стратегия) | ~4 МБ | ~0.4 мс | ~2 % |
  | 4 % | ~15 МБ | ~1.5 мс | ~8–10 % |
  | 7–10 % | ~30–40 МБ | ~3–4 мс | ~15–25 % |

- [гипотеза] В начале обучения, при почти равномерных стратегиях, холодные ветки теплее: w может быть 5–10 % и
  падать к сходимости. Проверка — замерить работу веток (`dist_plan.py measure`) на чекпоинтах 1M / 10M / 100M.
  Лекарство — пересобирать горячее и холодное на чекпоинтах: раскладка меняется между прогонами, числа при этом не
  меняются.

## (в) Ожидаемые ит/с [оценка]

**Скорость 5070.** Узел 5070 ≈ 3.4 × узел 3050: отношение одиночных тренеров на HU, 2.33M / 689k [замер раньше].
Узел 3050 — 353k в процессе [замер]. Значит, одна 5070 ≈ **~1.1–1.2M ит/с** при всём в VRAM. Размер таблиц на время
почти не влияет [замер: 16 и 64 корзины — 17.9 и 16.5 мс на пачку]. **Подтвердить в окне на ПК** (`bench/pc_window.ps1`).

| вариант | ит/с |
|---|---|
| 1 ПК, 256 корзин, горячее/холодное | ~1.1–1.2M при обученной стратегии; ~0.9–1.0M в начале, если w = 5–10 % |
| 1 ПК, 128 корзин, всё в VRAM (8.29 ГБ) | ~1.1–1.2M, та же скорость |
| 2 GPU по проводу: ПК + ноут 4060 по прямому гигабитному кабелю | ~1.3–1.4M (см. ниже) |

## (г) Что сделать сверх сделанного [оценка работы]

1. **Горячее/холодное в GPU-узле**, тип (а) — ~1 день с тестами:
   - холодные таблицы в `cudaHostAlloc(mapped)`;
   - бит «холодная» и базы в упакованных записях решения;
   - ядра выбирают указатель на элемент;
   - тест бит в бит с принудительной долей холодных веток на 3050.
2. **Планировщик:** горячее по работе на байт с потолком VRAM, пересборка на чекпоинтах — ~0.5 дня.
3. **Сохранение и загрузка кусками** (правило «32 ГБ без подкачки», пик +0.5 ГБ вместо +12 ГБ) — ~0.5 дня.
4. **Проверка памяти до старта** (отказ с понятной причиной вместо OOM) — ~2 часа.
5. **Выгрузка блюпринта 256 из файлов узла** без полной копии в памяти, если понадобится — ~0.5 дня.

Итого **~3 дня** для одного ПК. Бакетер 256 и его таблицы — отдельно, у основной сессии.

## Второй пункт: ПК + ноут 4060 по прямому гигабитному кабелю, «верх на 5070» (вариант 1)

- **Память:** 5070 ~10.5 ГБ + 4060 ~6.5 ГБ (8 ГБ минус буферы) = 17 ГБ ≥ 16.45 ГБ. Влезает без памяти хоста, но впритык:
  при нехватке холодное уходит в хост, как в варианте 3.
- **Раскладка по скорости:** 4060 ≈ 1.22 × 3050 ≈ 0.36 × 5070 [замер / оценка] → 5070 ~73 %, 4060 ~27 % работы веток.
  Верх считается один раз.
- **Обмен:** списки и значения только для переходов в ветки 4060 — ~27 % от 154 тыс. ≈ 42 тыс. × 16 Б = 0.67 МБ сырых
  (~0.2 МБ со сжатием) за пачку. По гигабиту ~6 мс против ~14 мс счёта пачки, конвейером прячется.
- **Итог:** ~1.36 × одна 5070 минус потери раундов и обмена ~10–15 % ≈ **~1.3–1.4M ит/с** [оценка]. Это ~+20–30 % к
  одному ПК.
- **Работа:** вариант 1 (~1 день) + всё из (г). Кабель и статические адреса на обоих концах, правило брандмауэра для
  порта узла — делает пользователь.
- Второй большой компьютер через интернет (~100 Мбит, пинг 5–15 мс) для обучения шагами не годится [оценка: 1 МБ за
  пачку ≈ 80 мс против ~14 мс счёта]. Годится только под независимые задания.

**Вывод:**
- 256 корзин на одном ПК влезает: горячее в VRAM, холодное (~6.5 ГБ, ≤ 1 % работы при обученной стратегии) в памяти
  хоста. Скорость на уровне 128 корзин целиком в VRAM, работы ~3 дня.
- ПК + 4060 по кабелю даёт ещё ~+20–30 % и запас памяти, но требует варианта 1 и кабеля.

**200 корзин (решение пользователя 13:45) [расчёт по замеренной работе веток; без `info_dec` (4 Б на строку)]:**
- таблицы 12.11 ГБ (464.9M ячеек, 196.9M строк);
- при 10–10.5 ГБ VRAM под таблицы в закреплённую память хоста уходит 1.6–2.4 ГБ (318–346 самых холодных веток,
  **0.02–0.08 % работы**) — штраф PCIe ничтожен;
- файл узла 9.2 ГБ;
- пик RAM кусками ~14–15 ГБ из 32; без кусков ~24 ГБ;
- ~1.1–1.2M ит/с на одной 5070 [оценка, подтвердить в окне].
