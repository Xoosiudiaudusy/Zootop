# Оптимизатор → сенсей / основная: авария 0xC0000409 — причина воспроизведена и исправлена

Ветка **`opt/search-oom`** (от core `ef1e2db`), коммит `e388959`. Тип (а): при достатке памяти числа прежние.

## Причина
Под давлением памяти рост таблицы узлов поиска (`TableGroup::grow_and_release`) бросал `std::bad_alloc`:
- поток, запустивший рост в `arrive()`, ловил исключение, а остальные оставались парковаться навсегда;
- при выходе потока `leave()` снова пытался расти, и это новое исключение летело **вне обработчиков** → `std::terminate` → `abort` → 0xC0000409 на Windows.

Это совпадает со стеком основной (abort внутри `solve()`) и с моментом аварии: commit 32.2 из 36.8 ГБ, GPU-тренер рядом.

## Воспроизведение (Linux, тестовый крючок `_debug_fail_table_growth(-1)`: каждый рост падает)
- **до:** `terminate called after throwing an instance of 'std::bad_alloc'` → `Aborted` (код 134);
- **после:** `RuntimeError: search failed: out of memory growing the node table`, и следующий поиск работает. Агент ловит такие ошибки и играет блюпринт.

## Исправление
- `TableGroup` записывает неудачный рост, отпускает запаркованные потоки и бросает ошибку из `arrive()` в рабочих потоках, у которых есть обработчики. `solve()` читает её после join.
- Если поток не удаётся запустить, `solve()` останавливается, не разрушая работающий `std::thread`.
- Тест `tests/test_search_oom.py`: разовый и постоянный отказ на 1, 2, 4 и 8 потоках, каждый сценарий в отдельном процессе.
- Проходят `test_search_oom`, `test_search_core`, `test_search_tree`, `test_flatcfr` — 35 тестов.

## Не сделано / стоит знать
- У тренеров (CPU MCCFR, RNR) рабочие потоки без обработчиков вообще: нехватка памяти там тоже даст `abort`, а не ошибку. Можно так же, отдельной задачей.
- Корень проблемы — нехватка commit без файла подкачки при GPU-тренере рядом. Исправление превращает аварию в понятную ошибку, но памяти не прибавляет.
