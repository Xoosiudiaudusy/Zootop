## H1: `--resume` без чекпоинта и выбор файла — исправлено
- **Нет чекпоинта** → отказ: «--resume: no checkpoint to continue … drop --resume to start a new run».
  Раньше обучение молча начиналось с нуля и перезаписывало блюпринт тега. Тест: папка остаётся пустой.
- **`.bin` и `.json` рядом** → берётся файл с большей итерацией (из заголовка, без загрузки). Время изменения больше не учитывается.
  - `.bin`: читается только заголовок, до 1 МБ.
  - `.json`: оба тренера пишут `"iteration"` первым полем, читаются первые байты.
  - При равенстве — `.bin` (так `--json` пишет пару).
  - Если итерацию одного из двух прочитать нельзя — отказ.
  - Тест: старый JSON на 1000 записан заново, то есть он новее по времени, рядом `.bin` на 3000 → продолжение с 3000; испорченный JSON рядом → отказ.
- **`fast.blueprint.tagged_path`** (блюпринты в `exploitability.py`, `search_demo.py` и др.) тоже по большей итерации, если оба файла её знают. Иначе, как раньше, по времени: у Python-JSON блюпринта итерации нет.

## M1: снимок финальной итерации — исправлено
- Финальная запись теперь всегда пишет `.it<N>` (CPU и GPU).
- У GPU-прогона имена снимков кратны пачке: `--checkpoint-every` округляется вверх до пачки, конец — всегда целые пачки. Записано в `docs/gpu_training.md`.
- Тест: CPU и GPU-эмуляция, 1024 итерации, чекпоинт каждые 512 → `.it512` и `.it1024`, затем `--resume` → `.it1536`.

## M3: параметры обучения хранятся и проверяются; паспорт — сделано
**Паспорт** `<файл>.run.json` пишется рядом с каждым чекпоинтом, блюпринтом и снимком `.it<N>`, атомарно (временный файл + rename). В нём:
- `train`: seed, batch, linear, linear_until, prune_below / prune_prob / prune_after / prune_relative / prune_scale_t, regret_floor;
- `run`: бэкенд, потоки, устройство (имя GPU / эмуляция / cpu);
- `game`: флаги игры и тег;
- `code`: git-коммит, `+dirty` при локальных правках;
- `written`: дата с часовым поясом, `host`;
- `history`: отрезки прогона через `--resume` — с какой по какую итерацию, код, устройство, потоки, настройки, начало.

**Проверка при `--resume`** (CPU и GPU одинаково):
- отказ, если `train` из паспорта отличается от флагов;
- сид сравнивается только при `--batch` (раздачи Philox); без пачек RNG продолжается из чекпоинта;
- флаг `linear` самого чекпоинта сверяется с `--no-linear` даже без паспорта. Раньше он молча перекрывал флаг.
- `--resume-override` — продолжить всё равно: печатает различия, паспорт сохраняет старые настройки в истории.

**`.gpu.json`:**
- больше не пишется: паспорт пишут оба пути, так что он не устаревает после продолжения на CPU;
- старый `.gpu.json` читается как паспорт, если нового нет.

**`scripts/blueprint_info.py FILE…`** печатает:
- тип и итерацию файла;
- игру из заголовка чекпоинта;
- паспорт и отрезки; `--json` — всё это одним JSON.

Файлы до 29.09 — «passport: none».

**Тесты** `tests/test_resume_safety.py` (12):
