## 2. Утверждения, которые прошу проверить (и как)

### У1. GPU даёт те же числа, что CPU-эталон пакетного режима, бит в бит
- Эталон — `Trainer::batch_size` (mccfr.h): итерации пачки читают снимок стратегии на начало пачки. Обновления применяются после пачки
  в порядке (ячейка, итерация, обходчик). Раздачи и сэмплы — Philox по адресу (seed, итерация, обходчик, хэш истории).
- Проверки:
  - `tests/test_flatcfr.py` и `tests/test_batched.py` — CPU-уровни, эмуляция ядер и GPU против эталона. На машине с GPU все три режима.
  - Включая остановку, чекпоинт и продолжение.
  - На ПК: 7 раундов, всегда IDENTICAL; HU100 100k итераций, 63 455 инфосетов.
- **Что оспорить.** Сам пакетный режим — другой алгоритм, чем обычный тренер (все итерации пачки видят одну стратегию).
  Бит в бит здесь значит только «GPU = CPU-версия того же пакетного алгоритма», а не «GPU = обычный тренер».

### У2. ~~Пакетный режим не ухудшает качество на итерацию~~ — ИСПРАВЛЕНО 27.09: ухудшает умеренно (ε +10–20 %, см. `2026-09-27_batch-epsilon.md`)
- Раунд 7: 3-max, широкая сетка (префлоп 0.5/1/3, постфлоп 0.5/1/2/4, 3 рейза), potential-exact 64.
  Дуэли по 1M раздач (3M рук на направление, ±1 bb/100). Итог = (A против двух B − B против двух A) / 2.

| сравнение при равном числе итераций | 79M | 767M |
|---|---|---|
| GPU 4096 против CPU | +0.2 | 0.0 |
| GPU 16384 против CPU | +0.2 и −0.1 (два сида) | −0.2 |
| контроль чувствительности: CPU 767M против CPU 79M | | **+4.3** |

- **Что оспорить.**
  - Одна игра, один набор корзин, дуэль «голова к голове», а не эксплуатируемость.
  - Итог «(A−B)/2» — моя свёртка двух направлений 3-max.
  - Раньше на HU 20M итераций пачка 65536 проиграла −11 bb/100: на коротких прогонах большие пачки вредны.
    Где граница по пачке и длине прогона, я не мерила.
  - В раунде 7 обе строки дуэли равных по силе стратегий слегка положительны (+0.4…+1.1). Моя гипотеза: одиночке выгодно играть
    против двух одинаковых копий. Не проверено.

### У3. GPU быстрее CPU в 7–10 раз на 3-max широкой (в 3–5 раз на HU узкой)
| игра | CPU 16 потоков | GPU 4096 | GPU 16384 |
|---|---|---|---|
| HU 100bb узкая, potential-exact 64 | 458k it/s | 1.37M (×3.0) | 2.25M (×4.9) |
| 3-max 100bb широкая, potential-exact 64 | 64.5k | 442k (×6.8) | 662k (×10.3) |

- На равном времени (раунд 6, 20 мин) GPU-блюпринт обыграл CPU на +3.8 / +4.4 bb/100 (контроль CPU/CPU = 0.0).
  Раунд 7 показывает, что это только за счёт числа итераций.
- **Что оспорить.**
  - CPU-тренер в замерах — обычный многопоточный, без прунинга. С прунингом он быстрее: в нашей дуэли ×1.3–1.4, но −0.9 bb/100.
  - Прунинга на GPU нет.

### У4. Быстрые дуэли: корзины через C++ и таблицу дают те же числа
- `compare_checkpoints.py` теперь по умолчанию берёт корзины из C++-бакетера и таблицы. При старте сверяет с Python-бакетером
  на 20 рук каждой улицы; при расхождении — ошибка. Старое поведение — флаг `--python-buckets`.
- На тестовой дуэли итог совпал до знака (−3.24), время 337 с → 2 с.
- **Что проверить:** `scripts/eval_archetypes.py` я не трогала (правило). Там, вероятно, та же медленность с potential-корзинами.

### У5. Точные признаки лучше Монте-Карло
- Замер шума Монте-Карло: при 16/64/256 корзинах в другую корзину, чем по точным признакам, попадает 17.5/39.7/68.2 % рук флопа
  и 14.2/32.5/52.4 % рук тёрна.
- **Дуэли «точные против МК» я не делала.** Это тип (б), в бой только по дуэли. Основная собиралась обучать точную 64.

### У6. Что влезает в память
- GPU, 12 ГБ: 3-max широкая 64 — замер 6.2 / 7.5 ГБ; 128 — ~10 ГБ, оценка; 256 — нет.
- 6-max не влезает никуда, это вопрос абстракции. Оценки по `count_betting_tree` — в `2026-09-25_1600_tree-size-questions.md`.

## 3. Решения за пользователем (мои рекомендации — только мнение)
1. **Вливать ли `opt/next` → `opt/exact-features` → `opt/gpu`** в основной проект, по порядку.
   Возможные конфликты: `bindings.cpp`, `mccfr.h`, `train_blueprint.py`, `trainer.py`. `search.h` я не трогала.
2. **Боевое обучение на GPU:** пачка 16384 (или 4096 для запаса), с `--checkpoint-every`. Нужна таблица корзин.
3. **Прунинг** в бою не включать (боевая дуэль: −0.9 ± 0.8 bb/100 при ×1.3–1.4 скорости). Переключатель есть, по умолчанию выключен.
4. **Точные признаки против МК** — дуэль, прежде чем переводить прод.

## 4. Как быстро проверить у себя
```
git fetch origin && git checkout opt/gpu
python scripts/build_fast.py --clean          # с CUDA 12.8+: "GPU trainer ON"; без CUDA всё работает как раньше
python -m pytest -q                           # ожидается 270 passed
python scripts/gpu_bench.py --emulate --check-iters 20000   # без GPU: ядра эмулируются на CPU, должно быть IDENTICAL
python scripts/gpu_bench.py                   # с GPU: IDENTICAL + скорость
```
Известный нестабильный тест: `test_search_core.py::test_our_average_is_accumulated_every_iteration`. Это статистический порог
в поиске при двух потоках: иногда падает под нагрузкой, отдельно проходит и на базовой ветке.

## 5. Мои известные слабые места
