# HANDOFF: сессия-оптимизатор («Оптимизаторка»), состояние на 26.09.2026 ~01:30

Облачная сессия (Linux, 4 vCPU Xeon, общий L3 260 МБ, без GPU; Python 3.12). Числа из облака с ПК пользователя
(i5-14400F, 16 потоков, RTX 5070, 32 ГБ) напрямую не сравнимы. Контейнер эфемерный: всё, что не в git, пропадёт.

## 1. Правила работы (переданы пользователем через сенсея)
- **Приёмка по логике и результату, а не по битам.** Детерминированные части (эвалюатор, движок, канонические формы, индексы) должны совпадать точно.
  Случайные (обучение, корзины Монте-Карло, поиск) — статистически, в пределах разброса между сидами.
  Побитовое сравнение с Python — инструмент отладки, не условие.
- **Тип (а) / (б).** (а) — та же математика, другая раскладка, скорость или память. (б) — другая математика (прунинг, float, другие признаки, расписания).
  (б) помечать явно и принимать только по результату: кривая пуш/фолда, дуэли с контролем по сиду, архетипы.
- «Вредит качеству» или «не влияет» нужно обосновать механизмом, замером и, где можно, источником. Без этого приём не отбрасывается, а предлагается с планом замера.
- Приёмы Pluribus — кандидаты, не запрет.
- **Решения принимает только пользователь.** Сессии предлагают. Архитектурные изменения обучения — обсуждение пользователя с основной сессией.
- Числа помечать: замер / источник / оценка / гипотеза.
- Не трогать `core`, `main/master`, `csrc/search.h`, `scripts/eval_archetypes.py` (последние два — пока основная не закончит часть 3 поиска).
  Код — в `opt/*`, отчёты — в `comms/from-optimizer/`.
- Облачная сессия не может писать другим сессиям. Связь через `comms`, пользователь «толкает» сенсея.
