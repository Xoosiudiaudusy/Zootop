## Как проверить на ПК (порядок)
Нужен **Python 3.12+**: `py_sum` в C++ повторяет компенсированный `sum()` из 3.12, на 3.11 побитовый тест падает.
```
git fetch origin
git checkout opt/bucket-table
python scripts/build_fast.py
python -m pytest -q                                   # ожидается: всё зелёное
python scripts/build_bucket_table.py --buckets data/buckets_<tag>.json --threads 16
    # -> data/bucket_tables/buckets_<kind>_<n>_<fingerprint>.npbt (~138 МБ),
    #    сверка с bucket() на 20 тыс. рук на улицу, при расхождении файл не пишется
set NEGPLURIBUS_BUCKET_TABLES=data\bucket_tables      # PowerShell: $env:NEGPLURIBUS_BUCKET_TABLES="data\bucket_tables"
python scripts/bench_opt.py --buckets data/buckets_<tag>.json --grid wide --threads 1,2,4,8,16
```
Для сравнения «до»: тот же `bench_opt.py` на ветке `core`. Скрипт `bench_opt.py` есть только в `opt/bucket-table`,
его можно скопировать в `core` без изменений. Сравнивать по **M nodes/s** на одинаковых `--warmup/--iters`.
Узлов на итерацию должно быть столько же, это проверка, что работа та же.

## Что меняется для пользователя обучения
- Без переменной `NEGPLURIBUS_BUCKET_TABLES` всё как раньше, плюс ускорение от дерева историй.
- С переменной `core_bucketer()` сам находит таблицу своего бакетера по fingerprint. Если таблицы нет, работает без неё.
  На пути к таблице не должно быть кириллицы (путь открывается как UTF-8 → wide API на Windows, но лучше не проверять).
- Форматы blueprint, чекпоинтов и корзин **не менялись**, identity бакетера та же.
- Многопоточно набор конкретных раздач теперь зависит от планирования потоков (распределение то же).
  Однопоточный режим детерминирован и равен Python.
