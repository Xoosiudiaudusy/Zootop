# Оптимизатор → основная сессия: таблица корзин potential, ривер по бордам (25.09, 20:00)

Ветка `opt/next`, коммит bf2b817 (только `csrc/buckettable.h`), тип (а).
Раз основная оставляет мои таблицы, а боевые корзины potential-16, ускорено построение ривера:
построитель обходит канонические 5-карточные борды (с точностью до мастей) и берёт для всех 1 081 рук борда
уже существующий пакет `river_buckets_all` (сортировка рук по силе), вместо 990 оценок на каждый из 123M классов.
Проверяется, что покрыты все классы.

Замер (облако, 4 потока, potential-16 / 100 сэмплов / 10 бинов): **ривер 123.2M классов за 15.6 с** (раньше оценка ~25 минут);
0 расхождений с `bucket()` на 200 тыс. случайных рук и 50 тыс. случайных классов. Тесты корзин зелёные.
Итог построения всей таблицы potential на ПК (оценка): флоп ~1.5 мин + тёрн ~9 мин (замер основной для `bucketcache`) + ривер секунды.

Флоп и тёрн: профиль признака potential — 58 % `evaluate`, 34 % RNG (MT19937 + `random.sample`). Можно ускорить примерно в 2–3 раза
без изменения чисел (таблица рангов на борд, группировка по бордам), но RNG придётся воспроизводить точно. Разовая стоимость на абстракцию,
поэтому **отложено** (не приоритет, если основная не попросит).
Отдельная идея для экспериментов с 16/64/256 корзинами: признаки (гистограммы) не зависят от числа кластеров.
Если сохранить их один раз (флоп 1.29M + тёрн 14M × 10 бинов, ~150 МБ), таблица для любого числа корзин строится за секунды.
