# Оптимизатор → основная сессия: таблица корзин potential, ривер по бордам (25.09, 20:00)

Ветка `opt/next`, коммит bf2b817 (только `csrc/buckettable.h`), тип (а).
Раз основная оставляет мои таблицы, а боевые корзины potential-16, ускорено построение ривера:
построитель обходит канонические 5-карточные борды (с точностью до мастей) и берёт для всех 1 081 рук борда
уже существующий пакет `river_buckets_all` (сортировка рук по силе), вместо 990 оценок на каждый из 123M классов.
Проверяется, что покрыты все классы.

Замер (облако, 4 потока, potential-16 / 100 сэмплов / 10 бинов): **ривер 123.2M классов за 15.6 с** (раньше оценка ~25 минут);
0 расхождений с `bucket()` на 200 тыс. случайных рук и 50 тыс. случайных классов. Тесты корзин зелёные.
Итог построения всей таблицы potential на ПК (оценка): флоп ~1.5 мин + тёрн ~9 мин (замер основной для `bucketcache`) + ривер секунды.

Флоп и тёрн: профиль признака potential — 58 % `evaluate`, 34 % RNG (MT19937 + `random.sample`). Можно ускорить примерно в 2–3 раза
без изменения чисел (таблица рангов на борд, группировка по бордам), но RNG придётся воспроизводить точно. Разовая стоимость на абстракцию,
поэтому **отложено** (не приоритет, если основная не попросит).
Отдельная идея для экспериментов с 16/64/256 корзинами: признаки (гистограммы) не зависят от числа кластеров.
Если сохранить их один раз (флоп 1.29M + тёрн 14M × 10 бинов, ~150 МБ), таблица для любого числа корзин строится за секунды.

## Решения пользователя (25.09, 20:30, пересказ; слова пользователя — в кавычках)
1. Прунинг: «Да проверять конечно через дуель». Запущено в облаке: HU 100bb, 4 улицы, узкая сетка, E[HS]-8, по 20M итераций:
   эталон (seed 0), прунинг −1e9 и −1e11 (после 2M итераций, 95 %; seed 0), контроль без прунинга (seed 1). Дуэли антисимметричные, итог сюда же.
2. Расписание Linear CFR: «Пока не меняем держим в уме». Переключатель добавлен и выключен по умолчанию: `--linear-until N` (коммит 84116ba).
3. Точный E[HS] на ривере: «давай сделаем если это быстро и точечно... Но блин я бы спросил у сессии на скок потенциально это на что повлияет,
   будет ли для нас положительный результат есть ли что то на этот счет в статьях мб кто то делал и изучал».
   **Вопрос к тебе:** что говорят статьи про шум Монте-Карло в E[HS]-корзинах (150–200 сэмплов, σ ≈ 0.03–0.04 по эквити)
   против точного расчёта? Насколько это меняет границы корзин и игру? Для боевых potential-16 это неважно (ривер уже точный),
   касается только E[HS]. Если пользы для боевых нет, предлагаю не делать.
4. Видеокарта — следующая большая тема, когда нечего будет делать. Распределённое обучение на нескольких машинах
   (у пользователя 3 машины + 1 в планах со 128 ГБ DDR4) — тоже в план, подробности пользователь даст позже.

## Результат дуэли по прунингу (облако, 25.09, 21:30) [замер]
HU 100bb, 4 улицы, узкая сетка (1 / 0.5, 1 / 2 рейза), E[HS]-8 (таблица корзин), 4 потока. Прунинг после 2M итераций, в 95 % итераций.
Дуэли по 200 тыс. раздач (400 тыс. рук в каждую сторону). Разница антисимметричная: ((A против B) − (B против A)) / 2, 95 % ДИ ≈ ±1.9 bb/100.

| A (против эталона: без прунинга, seed 0, 20M итераций, 141 с) | итераций | время | разница, bb/100 |
|---|---|---|---|
| контроль: без прунинга, seed 1 | 20M | 142 с | −1.0 (шум) |
| прунинг −1e11 | 20M | 90 с | +0.95 |
| прунинг −1e11 | 31M | 117 с | +1.16 |
| прунинг −1e9 | 20M | 42 с | **−3.0** |
| прунинг −1e9 | 60M | 101 с | **−2.1** |

Выводы (одна пара сидов, одна игра — предварительно):
- −1e11: качество в пределах шума, обучение в 1.6 раза быстрее при том же числе итераций. При равном времени не хуже.
- −1e9: теряет 2–3 bb/100 **даже при втрое большем числе итераций**. Потеря структурная, это не недоученность.
  Механизм [гипотеза]: при Linear CFR сожаления растут как t², абсолютный порог со временем отсекает всё больше,
  и отсечённые действия «замерзают». За 60M итераций это 101 с против 42 с за 20M при том же пороге, то есть отсекалось гораздо больше.
- Следующий шаг, если пользователь захочет: порог, растущий с t² (как предлагал сенсей), второй сид, широкая сетка / potential-16.
