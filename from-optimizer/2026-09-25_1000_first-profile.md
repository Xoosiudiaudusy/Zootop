## Профиль (callgrind, 1 поток, широкая сетка, 3 000 итераций, холодный старт)

| Где | Доля инструкций в train() |
|---|---|
| `EquityBucketer::bucket` → `ehs_canonical` (Монте-Карло E[HS]) | **≈ 73 %** |
|  └ из них `evaluate()` | ≈ 36 % |
|  └ `PyRandom::sample` / `randbelow` | ≈ 19 % |
|  └ `PyRandom::seed` (сид MT19937 на каждую форму) | ≈ 10 % |
| `HandState::apply` / `check_round_end` / `finish` | ≈ 8 % |
| строки ключей новых узлов (`infoset_key_for_bucket`, `from_concrete`) | ≈ 7 % |
| таблица узлов (хеш, поиск) | ≈ 3–4 % |

Кэш корзин почти не попадает (замер, 1 поток, 400 тыс. итераций): computes == size на всех улицах.
Размер кэша растёт на ~190 тыс. форм на 100 тыс. итераций и не выходит на плато.
Причина в числе канонических форм: флоп 1 286 792, тёрн 13 960 050, ривер 123 156 254
(источник: Waugh 2013, «A Fast and Optimal Hand Isomorphism Algorithm»). Кэш на 4М или 32М ячеек при
случайных раздачах попадает редко, и почти каждая итерация заново считает 200 сэмплов Монте-Карло на тёрне и ривере.
Этот профиль снят на коротком прогоне. На 50M итераций флоп целиком влезет в кэш, а тёрн и ривер
по-прежнему будут промахиваться (оценка по числу форм).

## Предложение 1 (тип (а), главное): корзины предрасчётом, по индексу

E[HS] корзина — детерминированная функция канонической формы: RNG сидируется хешем формы
(`ehs_canonical`, `csrc/abstraction.h`). Значит, можно заранее посчитать **всю** таблицу:
- флоп 1.29M, тёрн 13.96M, ривер 123.2M форм, по 1 байту на корзину: **~138 МБ** на всю игру (оценка);
- индекс формы через индексатор Waugh (почти константа) вместо перебора 24 перестановок мастей и хеш-кэша;
- в обучении корзина превращается в одно чтение из массива.

Значения корзин получаются **те же самые**: та же функция и те же сиды, просто посчитаны заранее.
Приёмка точная: на случайной выборке форм корзина из таблицы равна `bucket()`.
Стоимость предрасчёта: 123M форм × 200 сэмплов ≈ 2.5·10^10 оценок руки. На 16 потоках CPU это десятки минут
(оценка, уточню замером). На GPU это минуты, если перенести MT19937 и `random.sample` бит в бит
(это возможно, но работа отдельная). Один раз на абстракцию, и таблица ложится на диск.
Для potential-aware то же самое: гистограмма и k-means тоже детерминированы от формы (проверю).
**Ожидаемый эффект на обучение:** уходит ~70 % времени по профилю, то есть ~2–3× на итерацию (оценка).

## Предложение 2 (тип (а)): плотная таблица «история × корзина», без хеша и строк

Замер выше: различных историй в 8 раз меньше, чем инфосетов (7.7 тыс. против 63.6 тыс.,
33.6 тыс. против 275 тыс.). В среднем 2.6–2.7 действия на узел, а `Node` держит 8 слотов double.
- Дерево торгов строится один раз, `children[action]` вместо хеширования.
- Суммы ставок, банки и выигрыши терминалов (кто сколько вложил) считаются заранее. `HandState` в горячем цикле не нужен,
  на раздачу один раз считаются ранги рук на вскрытии.
- Узел — строка `[корзина][действие]` точной длины.
- Строки ключей не хранятся, а строятся при экспорте из пути по дереву.
  **Форматы файлов не трогаю:** экспорт выдаёт те же ключи.
- Память: ~16 Б × действий на инфосет при double против ~300 Б сейчас, то есть в 5–7 раз меньше (оценка).
  Во float ещё вдвое меньше, но это уже тип (б).

Эта раскладка — основа для батчевого обхода и GPU-варианта (объяснила пользователю в чате).

## Предложение 3 (тип (а)): динамическая раздача итераций

Вместо `t % T` — общий атомарный счётчик пачек по 64–256 итераций. RNG сидируется **номером итерации**,
а не потока, поэтому набор раздач останется детерминированным при любом числе потоков и любом их планировании.
