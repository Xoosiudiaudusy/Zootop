# NegativePluribus

Исследовательская песочница для 6-max No-Limit Hold'em: цель — построить бота уровня
Pluribus **плюс** адаптивный слой, который эксплуатирует статистику конкретных оппонентов
(идея StratFormer / AlphaExploitem), и честно измерить его в bb/100 с доверительным интервалом.

Чистый Python 3.10+, без обязательных зависимостей. Всё, что здесь есть, работает и покрыто тестами.

## Быстрый старт

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
```

Посмотреть абстракцию глазами (первый запуск подбирает границы бакетов, ~20 с):

```bash
python scripts/show_abstraction.py --board "Kh 9h 2c" --hands "Ah Qh,Kd 3d,9s 8s,7c 7d,As 5s"
```

Обучить первый blueprint на урезанной игре и сразу измерить его (2 игрока, 20bb,
торги на префлопе и флопе, около 2 минут; результаты в `data/`):

```bash
python scripts/train_blueprint.py --players 2 --stack 20 --street flop --iters 30000
```

Измерить blueprint линейкой, а не манекенами: точная эксплуатируемость пуш/фолд игры,
сверка с решением HRC и кривая ε от числа итераций (таблица эквити строится один раз, ~5 мин):

```bash
python scripts/exploitability.py pushfold --stack 10 --iters 30000
```

LBR-оценка снизу для флоп-blueprint'а (реальные карты, ренджи по бакетам blueprint'а):

```bash
python scripts/exploitability.py flop --tag 2p_20bb_flop --hands 200
```

Эксплойт-слой на маленькой игре с точной линейкой (все архетипы, около 5 минут):

```bash
python scripts/exploit_demo.py --opponents maniac,station,nit,lag,tag --hands 300
```

Посмотреть, как поиск в реальном времени меняет решение blueprint (нужен обученный blueprint):


## Как это использовать из кода

```python
from negpluribus.agents import make_agent
from negpluribus.eval import duplicate_match
from negpluribus.stats import StatsTracker

hero = make_agent("tag", seed=1)
villains = [make_agent(n, seed=i) for i, n in enumerate(["nit", "station", "maniac", "lag", "passive"])]
tracker = StatsTracker()
res = duplicate_match(hero, villains, n_deals=300, seed=0, tracker=tracker)
print(res)                       # bb/100 +/- 95% CI, по позициям
print(tracker.report())          # HUD всех игроков
vec = tracker.players["maniac"].feature_vector()   # 40 чисел: вход для эксплуатирующей политики
```

Свой бот — это класс с методом `act(obs) -> Action`. В `Observation` есть всё, что видно
за столом: карты, борд, банк, to_call, стеки, позиция, история действий этой раздачи,
границы легального рейза; `obs.clamp_raise(x)` превращает любой желаемый сайзинг в легальный.

## Метрика

Две линейки. **Эксплуатируемость ε** (bb/100): сколько идеальный оппонент, знающий стратегию,
выигрывает сверх её собственной ценности; 0 = Нэш. Для 2-player игр с торгами только на префлопе
считается точно (`cfr/exploit.py`), для игр с постфлопом — оценка снизу через LBR. Это метрика для
blueprint'а: выбор абстракции, критерий остановки обучения, λ(ε) в эксплойт-слое.

**bb/100 против оппонентов** при 95% доверительном интервале — метрика для эксплойт-слоя и поиска. Одна «выборка» для интервала — это одна
колода, сыгранная во всех ротациях, поэтому корреляция внутри дубля не занижает интервал.
Ориентир: Pluribus против профи показал 48 mbb/раздачу (4.8 bb/100) при p = 0.028 на
10 000 руках только благодаря AIVAT. Без снижения дисперсии 5 bb/100 в 6-max требуют
порядка 150 000 рук. Против друзей набрать такое нельзя, поэтому измеряем против
ботов-архетипов, а живую игру считаем демонстрацией.

## Известные упрощения (намеренные)

* Архетипы оценивают силу руки как эквити против *случайных* рук, а не против ренджа.
  Поэтому они фолдят реже, чем люди (WTSD высокий). Для их роли (стабильные,
  систематически ошибающиеся оппоненты) это приемлемо; пороги в `Style` легко подкрутить.
* Короткий олл-ин ре-открывает торги для всех (в казино тот, кто уже действовал, не может
  ре-рейзить). На исследование это не влияет.
* Нет AIVAT: он требует функцию ценности, появится вместе с blueprint.
* Парное сравнение двух героев на одинаковых раздачах честно только при общем потоке случайности:
  герой сеется по слоту, а не по имени (иначе два одинаковых бота с разными именами «различаются»
  на десятки bb/100 при 400 руках — проверено).
* Поиск в реальном времени в чистом Python успевает 600–1500 итераций на решение; этого мало, чтобы
  решить субигру с нуля, поэтому он стартует от blueprint как от приора и уходит от него только там,
  где находит сильное основание. Точечное сэмплирование своей руки, накопление средней стратегии с
  весом собственного reach и общие случайные числа по ветвям снижают шум; RM+ с сэмплированием
  раздувает шумные агрессивные действия и выключен.

## План (см. docs/research.md)

1. ✅ Движок, эвалюатор, архетипы, HUD-трекер, дублирующая оценка, учебный CFR.
2. ✅ Абстракция: изоморфизм мастей, бакеты рук по E[HS], сетка сайзингов с pseudo-harmonic
   отображением, ключ инфосета. ✅ Potential-aware бакеты (пункт 10b): тот же интерфейс,
   `GameSpec(bucket_kind="potential")`, C++-порт бит в бит; что они дают на маленькой игре и
   почему 8 корзин на улицу — мало для них, см. docs/buckets.md.
3. ✅ MCCFR blueprint на урезанной игре (GameSpec): external sampling + Linear CFR, чекпоинты,
   BlueprintAgent, измерение против манекенов. Масштабирование на 6-max/100bb/4 улицы — вопрос
   вычислений (RunPod) и ускорения движка, не кода.
3b. ✅ Линейка эксплуатируемости: точный best response для 2-player префлоп-игр, сверка с HRC,
   кривая ε от итераций; LBR снизу для флоп-игр. Для 3+ игроков только LBR одного места против
   замороженных остальных (верхняя граница дыры, не расстояние до Нэша).
4. ✅ Поиск в реальном времени с ограниченной глубиной и 4 смещёнными стратегиями продолжения
   (трюк Pluribus). Точки входа для статов: `ContinuationPolicy.bias_factors(seat)` (какое
   продолжение ждать от этого оппонента) и `RangeSampler` (рендж оппонента из его статов, а не
   из blueprint).
5. Эксплуатирующий слой на маленьких играх, модельный.
   ✅ 5 v1: частоты трекера → модель (blueprint в log-odds) → доверие p из ε модели (аналог λ(ε)
   StratFormer) → Restricted Nash Response → прирост над blueprint и цена в ε.
   ✅ 5а: модель по силе руки: контексты по истории улицы, наклоны по силе показанных рук,
   вес blueprint'а тает с числом вскрытий. Маньяк, которого частотная модель не брала, теперь
   эксплуатируется.
   ✅ 5б: модель в поиске на флоп-игре: RangeSampler считает рендж оппонента по его модели,
   ContinuationPolicy строит четыре стратегии продолжения поверх модели (SearchAgent(...,
   opponent_model=...)); измерение — парное сравнение четырёх героев против архетипов.
   5в: нейросетевая политика (StratFormer как есть, GPU) после больших blueprint'ов.
6. AIVAT-оценка, затем игра с людьми.
